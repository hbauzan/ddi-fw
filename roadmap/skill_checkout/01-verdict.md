## What is actually restricted

Three different things get called “restriction”. Keep them separate.

1. **Product doors that must stay locked** (not a skill bug): cosine-as-verdict, gap epsilon, speculative streaming, silent float rounding in exports, fail-open on empty clause / unpublished lock, merging Deletor into `main` by accident.
2. **Process gates that slow or refuse legitimate lab work** (skill bug / misfit): “do not read code before a red-capable command”; TDD-minimal for `--no-prune` measurement; “if architecture is closed, do not reopen”; ask-before-every-hypothesis; git commit-freely vs human “commit only when asked”.
3. **Context tax** (not a capability cap, still harmful): mandatory sandwich + quote rotation; Hugging Face plugin skills advertising themselves for “AI and ML in general”; `lessons-learned.md` plus `murray.md` plus `SKILL.md` all restating persona.

## The analogy that must not be over-read

The protocol is **release engineering** sitting on a **geometry laboratory**. It does not confiscate the boat. It charges a toll on every mile of lab work.

Remediation is not “delete the skills”. Remediation is **split modes** (release vs research), **demote persona**, **narrow axiom wording**, **fix phantom-file claims**, **pick one git constitution**.
